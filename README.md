# 서울 에어비앤비 RevPAR 수익 최적화 가이드

서울 Airbnb 32,061개 리스팅 중 실제 운영 중인 14,399개를 분석해,  
호스트가 직접 바꿀 수 있는 변수로 객실당 수익(RevPAR)을 최적화하는 전략을 대시보드·자동화까지 구현한 프로젝트

- 데이터: Inside Airbnb 서울 리스팅 (2024-10-01 ~ 2025-09-30, 12개월) · 25개 자치구 · 42개 변수
- 기간: 2026.02 ~ 2026.03 · 3인 팀 프로젝트

---

## 1. 문제 정의 (Why)

전체 리스팅의 54.3%(17,399개)는 비활성 숙소다.  
→ 전체 숙소의 RevPAR 중위값은 ₩8,868이지만, 실제 운영 숙소(14,399개) 기준으로는 ₩47,850으로 **5.4배 차이**가 난다.  
→ 호스트는 가격을 낮추면 수익이 줄고, 올리면 예약이 줄어드는 딜레마에 빠져 있다.

**핵심 질문:**
> 가격이 아니라 점유율이 수익을 결정하는가? 그렇다면 점유율을 높이는 변수는 무엇인가?

분석 대상: Active+Operating 14,399개 (전체 32,061개 중 44.9%)

## 2. 핵심 인사이트 (What)

| 발견 | 결론 | 수치 | 근거 |
|------|------|------|------|
| RevPAR 분산 분해 (log) | ✅ 점유율이 수익 변동을 가장 많이 설명 | 점유율 **58.2%** / ADR **37.5%** / 교호작용 4.5% | `01c` |
| 가격 인하 효과 | ❌ 가격 인하 ≠ 점유율 상승 | 가격과 예약률은 독립적으로 움직임 | `01c` |
| 호스트 통제 변수 최우선 레버 | ✅ 슈퍼호스트 | RevPAR **+83.1%** | `01` |
| 비활성 구조 | ✅ 시장 절반이 운영 중단 | 비활성 **54.3%** | `00` |

**호스트가 오늘 바꿀 수 있는 5가지**

| # | 항목 | 결과 | 근거 |
|---|------|------|------|
| 1 | 슈퍼호스트 | 슈퍼호스트 RevPAR **+83.1%** (평균 ₩79,087 vs ₩43,201) | `01` |
| 2 | 사진 수 | **21~35장** 구간에서 RevPAR 차이가 유의 (1~10장 → 21~30장 +110%) | `01`, `11` |
| 3 | 최소 숙박일 | **2~3박**에서 RevPAR 최대 (중위값 ₩56K), 예약률은 4~7박에서 최대 (60%) | `01c` |
| 4 | 추가요금 | 7인 이상 숙소에서 추가요금 부과 시 RevPAR **-55.9%** (소형 숙소 -25%) | `11` |
| 5 | 평점 | 만점(5.0)보다 **4.85~4.95** 구간이 점유율 최고 (0.622) | `01c` |

**슈퍼호스트 × 예약방식별 RevPAR 중위값** (`01`)

| 그룹 | 중위값 | n |

| 슈퍼호스트 + 즉시예약 | ₩63,708 | 3,198 |
| 슈퍼호스트 + 수동승인 | ₩59,497 | 4,930 |
| 일반 호스트 + 즉시예약 | ₩32,863 | 2,735 |
| 일반 호스트 + 수동승인 | ₩30,846 | 3,536 |

### 전처리

- 원본 32,061행 × 42열 → 외부 데이터 병합(관광지 정보·생활인구) → 이상치 제거(최소 숙박일 > 730일, 평균 객실가 ≥ 2,000,000원) → 운영 숙소 14,399개 서브셋 분리 → 피처 엔지니어링
- 제외 컬럼: cleaning_fee, country, currency, locality, region / exng, ttm_exng(상수) · nearest_poi_image(23.9% 결측)

- 데이터 한계: 일자별 로그가 아닌 90일 / 12개월 집계 데이터라 세부 시계열 분석에는 한계가 있음

## 4. 통계 검증

- 표본: n=14,399 (Active+Operating)
- 방법: Spearman 상관계수 · Mann-Whitney U 검정 · Kruskal-Wallis 검정 (비모수)
- 유의수준: 모든 검정 p<0.001
- 결과: **9개 가설 중 7개 채택**, H8·H9 부분 채택(자치구 소표본 n=25)

| 가설 | 내용 | 결과 | 핵심 수치 |
|------|------|------|---------|
| H1 | 슈퍼호스트 → 수익 프리미엄 | ✅ 채택 | +83.1% |
| H2 | 숙소 유형 → 수익 구조 차이 | ✅ 채택 | 전체숙소 2.7배 |
| H3 | 사진 수 → 수익 (비선형) | ✅ 채택 | 21~35장 구간 유의 |
| H4 | 최소숙박일 → 수익 | ✅ 채택 | 2~3박 최적 |
| H5 | 추가요금 정책 → 수익 | ✅ 채택 | 7인↑ -55.9% |
| H6 | 공급 집중 → 수익 하락 | ✅ 채택 | 마포구 리스크 |
| H7 | 관광지 유형 → 수익 | ✅ 채택 | 여행코스 최고 |
| H8·H9 | 자치구 인구·시장 구조 | ⚠️ 부분 채택 | 자치구 소표본 n=25 |

**대시보드 로직 검증** (`10`): 요금 구간과 호스트 등급은 각각 RevPAR 차이를 유의하게 설명하지만(Kruskal-Wallis p<0.001), 두 기준 간 연관은 약함 (χ²=296.2, p<0.001, Cramér's V=0.10) → "등급별 적정 가격"처럼 보이는 화면 표현을 수정

## 5. 모델링

### 이중 예측 모델 (Dual Model)

Model A(시장 적정 요금 예측: 위치·규모·관광지) → 가격 차이 계산(현재 요금 − 적정 요금) → Model B(점유율 예측: 리뷰·평점·사진 + 가격 차이) → 최종 보정

> 요금과 점유율은 서로 다른 요인이 결정하므로, 분리해야 호스트가 각각 조절할 수 있다.

### 모델 성능 비교 (`03`, 5-Fold CV)

| 모델 | 검증 R² | 테스트 R² | 평균 오차(MAE) | 오차율(MAPE) |
|------|------|------|------|------|
| **LightGBM ★** | **0.847** | **0.85** | **₩19,554** | 32.6% |
| Random Forest | 0.744 | 0.75 | ₩24,470 | 45.6% |
| Ridge (선형) | 0.579 | 0.57 | ₩27,595 | 70.4% |
| Dummy (기준선) | -0.025 | -0.02 | ₩40,050 | - |

- 타겟: `log1p(ttm_revpar)`
- 데이터 누수 방지: 수익에서 직접 파생된 변수(지역 중위값 대비 수익, 수익 추세, 요금 효율성)와 점유율·요금·매출 등 6개 변수 제외

### 핵심 변수 → 호스트 액션 (SHAP, `03`)

| 순위 | 변수 (mean \|SHAP\|) | 호스트 액션 |
|------|------|------|
| 1 | 리뷰 수 (0.51) | 리뷰 요청 자동화 |
| 2 | 리뷰 전환율 (0.33) | 체크아웃 후 리마인더 |
| 3 | 평점 (0.12) | 4.85~4.95 유지 |
| 4 | 최소숙박 (0.08) | 2~3박 설정 |
| 5 | 사진 수 (0.07) | 21~35장 업로드 |
| 6 | 추가요금 정책 | 7인↑ 요금 제거 |
| 7 | 숙소 유형 | 전체숙소 전환 |

### 숙소 건강점수 (0~100점, A~F 등급)

리뷰 신호 · 사진 품질 · 예약 정책 · 위치 · 숙소 구성 각 20% — 같은 지역·같은 유형 숙소 대비 상대 점수

| 등급 | 점수 | 의미 |
|------|------|------|
| A | 80점↑ | 상위 20% — 현재 전략 유지 |
| B | 60점↑ | 양호 — 1~2가지만 고치면 A |
| C | 40점↑ | 보통 — 즉각 개선 필요 |
| D | 20점↑ | 취약 — 여러 개선 필수 |
| F | 20점↓ | 위험 — 전면 재점검 필요 |

## 7. 대시보드 + 자동화 (Results)

- **호스트 컨설팅 수익 예측 도구 (Streamlit)**: 시장 위치 4분면 · 건강점수 게이지 · 수익 예측 KPI · 시장 진단(적정 요금 vs 현재 요금)
- **리스크 탐지 자동화**: 32,061건 전체 스캔 → 총 16건 플래그(0.05%), HIGH RISK 1건

| 규칙 | 내용 | 검출 |
|------|------|------|
| R1 유령수익 | 리뷰 0 + 수익 > 1천만 | 14건 |
| R2 점유율-수익 불일치 | 점유율 0% & 수익 > 0 | 8건 |
| R3 가격 이상치 | 1일 평균 금액 > 구평균+3σ | 3건 |
| R4 유령 액티브 | 활성화 숙소 & 수익 < 5백만 | 5건 |
| R5 평점 없는 고수익 | 수익 > 1천만 & 평점 없음 | 2건 |

- 흐름: 데이터 변경 감지(`hooks.py`) → 5규칙 검사(`detector.py`) → 통계 보조 검사(`scorer.py`) → 위험도 산출 + 7일 중복 필터 → 이메일 발송(`email_alert.py`)

### 실행 방법

```bash
pip install -r requirements.txt
streamlit run dashboard/app.py
python3 risk_detection/hooks.py --trigger manual   # 리스크 자동 감지 (수동 실행)
bash setup_cron.sh                                  # 매주 월요일 오전 8시 자동 스캔 + 이메일 알림
```

> raw 데이터(`data/raw/`)는 용량·보안 문제로 미포함. 노트북에는 실행 결과가 저장되어 있으며, `02_host_preprocessing` 이후 단계는 `data/processed/`로 재현 가능.
